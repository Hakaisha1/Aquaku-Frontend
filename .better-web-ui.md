# Aquaku UI direction

## Design Context

### Users

Hobiis aquascape pemula dan aktif serta toko lokal Semarang. Mereka menemukan tanaman, fauna, alat bekas, berdiskusi tentang perawatan, dan membagikan tank. Transaksi MVP melalui WhatsApp/COD/meetup; bukan checkout atau pembayaran internal.

### Brand Personality

Alami, tenang, akrab. Bahasa Indonesia yang jelas dan percakapan, tanpa promosi berlebihan. Identitas menggunakan logo asli `public/logo.png`.

### Aesthetic Direction

Explicit user choice: gabungan Reddit (feed, sidebar kategori, komentar bertingkat; tanpa voting) dan Tokopedia (pencarian, kategori, filter, kartu produk, halaman detail). Beranda gabungan dengan marketplace lebih dominan. Mobile-first, light dan dark mode. Putih/netral dengan hijau dari logo; foto aquascape sebagai konteks nyata, bukan ilustrasi dekoratif.

Palette: canvas #f6f8f5, surface #ffffff, ink #26352c, muted #5f6c62, action green #34752b, logo accent #68c516. Dark canvas #121b16, surface #1a261e, ink #edf3e9, action #9cdb83. Satu keluarga Manrope; hierarki melalui ukuran dan berat, bukan label uppercase.

### Implementation Defaults

Existing stack takes precedence: Next.js 16 App Router, React 19, TypeScript, Tailwind CSS 4 via Turbopack, alias @/\*. No existing component/form/table/virtualization library or shadcn config. Use small reusable local components and native semantic controls for this first artifact, lucide-react for icons and next-themes for persisted accessible theme switching. Do not install an entire primitive/block system for a handful of controls. Future complex forms/tables/long lists default to TanStack Form/Table/Virtual when needed, not prematurely. Neither Radix nor Base UI is currently installed. Framework defaults reference mentioned by the setup skill is absent from the installed skill; preserve detected stack and explicit user preferences rather than invent configuration.

### Design Principles

1. Put discoverable products and local seller context before promotional claims; keep discussion reachable without mixing every content type into one feed.
2. Keep surfaces neutral and calm; green indicates identity, selection, and primary actions, not every border and paragraph.
3. Use original aquarium photography and meaningful condition/COD tags; never present simulated stock, ratings, or transactions as verified real data.
4. One clear primary action per view: explore listings, read a discussion, or contact a seller. No cart/checkout or upvote/downvote in this stage.
5. Mobile touch targets, keyboard focus, contrast, reduced motion, empty states, and light/dark parity are baseline requirements.

## First implementation

Routes: /, /marketplace, /marketplace/[slug], /forum, /forum/[slug]. Data is explicitly a frontend demo, not connected to an API. Search/filter/sort, photo selection, bookmarks, local comment replies, theme, and navigation should work; seller contact must explain that no actual WhatsApp seller number is configured. Local forum posts and replies persist in versioned browser storage, share comment counts across routes, and use browser-local detail URLs; notices must distinguish them from public, server-backed discussions and explain memory-only fallback when storage fails.

## Source-based design exploration

The agreed default is direction 1. An optional /preview route compares five real home compositions with the same product/discussion content, not five recolors:

1. Pasar hijau (recommended): compact photo-led welcome, category strip, marketplace grid, then community; best match for marketplace-first brief.
2. Katalog langsung: search/category/product-first density with a small welcome rail; fastest for repeat shoppers.
3. Jurnal tank: a large tank story and associated products before community; best for visual discovery, larger image budget.
4. Pasar tetangga: local seller/COD context and horizontal product rows; best for local trust and scanning, less initial grid density.
5. Ruang komunitas: split discussion/product columns on desktop and marketplace-first stacking on mobile; best for balancing discovery and conversation.
   Each is component/pattern-led and preserves the common shell, accessibility, responsive behavior, and usable product links.
